# Answervice 유저플로우

| 항목 | 내용 |
|---|---|
| 문서 설명 | Answervice의 사용자 흐름, 메뉴 구조, 화면 목록, 상태 처리를 정의한 유저플로우 문서 |
| 문서 분류 | 일반 문서 |
| 버전 | v1.0 |
| 문서 기준일 | 2026-08-23 22:15 |
| 작성·수정 | AI 에이전트(Sisyphus) · 화면설계서 v7.1의 승인된 화면 ID 기준 통합 재정의 |

> 화면 수치·분석 결과는 합성 예시 데이터다. 목업 존재가 DataHub·Trino·AI·백엔드 연결 완료를 의미하지 않는다.

## 1. 역할별 진입 흐름

```
접속 (/) ── 인증 안 됨 ──→ /login (SCR-AUTH-001)
   │                          │ 로그인 성공
   └── 인증 됨 ─────────────→ /agent (SCR-CHAT-001)
```

| 역할 | 허용 범위 |
|---|---|
| 일반 사용자 | 분석 챗, 허용된 보고서 조회 |
| 관리자 | 분석 챗 + 보고서 전체(편집·승인·실행) |
| 데이터·시스템 관리자 | 카탈로그·연결·Context·운영·감사 |
| 감사자 | 운영·감사 조회 |

권한 밖 메뉴는 숨기고, 직접 URL 접근도 서버에서 다시 거부한다. 사용자가 자신의 role을 바꾸는 기능은 없다.

## 2. 메뉴 구조와 라우트

```
Answervice
├─ 분석 챗            /agent                    SCR-CHAT-001  P0
├─ 보고서
│  ├─ 목록            /reports                  SCR-RPT-001   P0
│  ├─ 상세            /reports/:id              SCR-RPT-002   P0
│  ├─ 편집            /reports/:id/edit         SCR-RPT-003   P0
│  ├─ 실행 이력        /reports/:id/runs         SCR-RUN-001   P0
│  └─ 실행 상세        /reports/:id/runs/:runId  SCR-RUN-002   P0
├─ 데이터 카탈로그 (P1)
│  ├─ 자산 검색        /catalog                  SCR-CAT-001
│  ├─ 자산 상세        /catalog/assets/:id       SCR-AST-001
│  ├─ 연결 상태        /catalog/connections      SCR-CONN-001
│  └─ Context·정책     /catalog/context          SCR-CTX-001
└─ 운영·감사 (P0)
   ├─ 요청 검색        /operations/audit         SCR-AUD-001
   └─ 요청 trace       /operations/audit/:reqId  SCR-AUD-002
```

Tool 관리·문서 RAG·ML-as-a-Tool·고객 360·외부 배포는 범위 제외 — 메뉴와 route 모두 차단.

## 3. 핵심 플로우: 질문 → 보고서

```
1. 질문 입력 (/agent)
   "7월 마지막 주 객실 매출 감소 구간을 찾고, 예약 채널과 연회 일정 변화를 비교해줘"
        ↓
2. 처리 단계 표시        조건 확인 → 컨텍스트 검증 → SQL 생성
                        → SQL 안전성 검증 → 조회 실행 → 결과 검증 → 설명 생성
        ↓
3. 결과 확인             요약·KPI·표·차트 + 근거 패널
                        (원천·URN·metric·filter·as_of 표시)
        ↓
4. 보고서에 담기          분석 결과가 Artifact ID·출처를 유지한 채
                        보고서 초안에 블록으로 추가
        ↓
5. 편집 (/reports/:id/edit)   12열 배치·크기·문구 편집 → 저장(DRAFT)
        ↓
6. 승인·실행 (/reports/:id)   초안 승인(APPROVED) → 수동 실행 또는 스케줄
        ↓
7. 이력·감사                /runs 실행 결과·부분 실패 확인
                           /audit 질문부터 결과까지 trace 추적
```

화면 공통 원칙: 결과 가까이에 기간·단위·필터·기준 시각·출처를 표시한다. 질문 전송 전에는 결과를 숨긴다. 프론트엔드는 서버 값 그대로 표시하고 재계산하지 않는다.

## 4. 안전한 중단 (오류·예외 흐름)

| 상황 | 화면 처리 | 사용자 행동 |
|---|---|---|
| 조건 부족 (지표 0·2개 이상) | 필요한 기간·대상·지표를 다시 묻음 | 조건 보완 후 재질문 |
| 권한 부족 | 허용되지 않은 자산 안내 | 허용 화면으로 이동 |
| 안전하지 않은 조회 | 실행하지 않음 + 안전한 질문 예시 제공 | 질문 수정 |
| 일부 원천 장애 | 성공 수치와 실패 원천 분리 표시(`PARTIAL`) | 실패 범위만 재시도 |
| 근거 부족 | 설명·보고서 삽입 차단 | 조건 보완 |
| 시스템 오류 | 안전한 오류 범주 + `trace_id` | 재시도 또는 관리자 문의 |

## 5. 상태 모델

| 상태 | 사용자에게 보이는 것 | 가능한 행동 |
|---|---|---|
| `LOADING` | 처리 대상·진행 단계 | 대기(중복 제출 방지), 가능 시 취소 |
| `EMPTY` | 0건인 조건과 기간 | 필터 수정·새 질문 |
| `READY` | 검증된 결과와 근거 | 탐색·편집·보고서 전달 |
| `DELAYED` | 지연 원천·최근 정상 시각 | 허용된 재시도 |
| `PARTIAL` | 성공·실패 범위, stale 여부 | 성공 확인·실패 재시도 |
| `ERROR` | 오류 범주 + `trace_id` | 재시도·관리자 문의 |
| `FORBIDDEN` | 부족한 권한·허용 화면 | 허용 화면 이동 |
| `INSUFFICIENT_EVIDENCE` | 부족한 기간·지표·근거 | 질문 보완(보고서 삽입 불가) |

보고서 상태: `DRAFT → APPROVED → RUNNING → SUCCESS / PARTIAL_SUCCESS / FAILED`. 승인본은 변경하지 않고 새 버전으로 편집한다.

## 6. 보조 플로우

### 6.1 데이터 카탈로그 (데이터 관리자)
5개 원천 상태 확인 → 자산 검색 → 자산 상세(URN·schema·owner·lineage·Trino mapping) → 연결 상태(ingestion·catalog·오류) → Context·정책(승인 metric·time·JOIN·mask, 읽기 전용).

### 6.2 운영·감사 (관리자·감사자)
요청 검색(역할·정책·보존 상태 필터) → 요청 trace timeline(질문→조회→결과→보고서 단계별) → 권한 있는 JSON export. 개인정보·credential·모델 내부 추론은 노출·내보내기하지 않는다.

### 6.3 접근성·반응형 기준
- 모든 입력에 label·오류 설명 연결, 색상 외 문구·아이콘 병행, 차트에 표/핵심 수치 병렬 제공, dialog 키보드 focus·Escape·focus 복귀, 비동기 상태 `aria-live` 전달.
- 1440px↑ sidebar+패널 / 1025~1440px 패널 축소 / 769~1024px drawer 전환 / ≤768px 단일 열(블록 y→x 순서). 작은 화면에서도 근거·오류·핵심 행동을 숨기지 않는다.
