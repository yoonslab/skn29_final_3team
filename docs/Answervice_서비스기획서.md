## 1. 제품 정의

**Answervice는 여러 부서에 흩어진 데이터를 자연어 질문으로 안전하게 분석하고, 검증된 결과를 반복 실행 가능한 보고서로 만드는 기업 내부 서비스다.**

- 사용자는 "이번 달 핵심 지표가 얼마예요?"처럼 자연어로 질문한다.
- 시스템은 여러 부서 데이터를 조회해 표·차트·출처를 함께 제공한다.
- 검증된 분석은 근거가 보존된 채 보고서에서 반복 사용된다.

대상 데이터: 워커힐 호텔 앤 리조트 운영 환경을 모사한 **합성 데이터**(실제 고객 데이터 미사용, deterministic seed·schema version 기록).

## 2. 해결하는 3가지 문제

| # | 문제 | 현재 | Answervice 해결 |
|---|---|---|---|
| 1 | 데이터가 여러 시스템에 분산 | 담당자에게 매번 위치를 물어야 함 | DataHub 메타데이터에서 한곳에 검색 |
| 2 | 조회에 SQL 능력 필요 | 개발자가 아니면 조회 불가 | 자연어 질문 → 시스템이 검증 후 자동 실행 |
| 3 | 보고서에서 근거 소실 | 수치만 옮겨 조건·출처가 사라짐 | 결과+조건+출처를 보존해 반복 재실행 |

핵심 원칙: **AI 단독 신뢰가 아니라 검증 + 추적 + 재사용**이 함께 되어야 신뢰할 수 있는 분석이다.

## 3. 사용자와 역할

| 역할 | 하는 일 | 필요한 것 |
|---|---|---|
| 일반 직원 | 자연어 질문 → 결과 이해 | 표·차트·조건 설명·근거 |
| 관리자 | 보고서 편집·승인·정기 실행 | 어떤 데이터를 언제 마지막으로 실행했는지 |
| 데이터·시스템 관리자 | 원천 연결·권한·정책 관리 | 어디서 무엇을 조회했는지 기록 |
| 감사자 | 권한·실행 증적 확인 | 질문부터 결과까지 전체 trace |

## 4. 핵심 사용자 시나리오

### A. 분석 질문 (P0)
마케팅 담당자가 "지난달 VIP 고객 구매액이 얼마야?"라고 질문 → 시스템이 데이터 검색 → 안전성·권한·정확성 검사 → 표·차트·조건과 함께 제시 → "보고서에 담아"로 출처와 함께 저장.
성공 기준: 화면 수치 = 실제 데이터셋 + 적용 조건과 일치.

### B. 정기 보고서 (P0)
주간 경영 보고서의 지난 분석 블록을 이번 주 데이터로 자동 재실행 → 결과 검토 후 승인 → 매주 같은 시간 자동 실행. 한 블록이 실패해도 나머지는 계속 실행(부분 성공 지원).

### C. 새 데이터 원천 추가 (P1)
새 시스템 등록 → 메타데이터 자동 수집 → 기존 질문 재실행 → 새 원천까지 조회·출처 표시 확인. 화면 표시만으로 끝내지 않고 실제 조회에 사용되어야 한다.

### D. "왜" 질문 (P2 — 범위 제외)
"매출이 떨어진 이유는?" → 데이터 감소 관측 + 정책 변경 기록을 분리 제시하고 하나만으로 결론 내리지 않음. 현재 프로젝트 범위 밖.

## 5. 제공 범위

| 우선순위 | 범위 | 내용 |
|---|---|---|
| **P0 필수** | 분석 챗 + 보고서 | 질문 → 검색 → 검사 → 표·차트·출처 제시 / 결과 저장 → 수동·스케줄 실행 |
| **P1 추가** | 데이터 카탈로그 | 5개 원천의 위치·소유자·상태 확인, 신규 원천 자동 검색 |
| **P2 제외** | 확장 기능 | 사내 문서 RAG, 예측 모델 연동(ML-as-a-Tool), MCP, 고객 360, 외부 보고서 배포 |

## 6. 성공의 정의

목업이나 설치 완료가 아니라 **end-to-end 동작**이 성공 기준이다.

| 상황 | 요구 동작 |
|---|---|
| 정상 질문 | 올바른 데이터를 표·차트·출처와 함께 제공 |
| 모호한 질문 | 임의로 답하지 않고 필요한 조건(기간·고객군·지표)을 다시 물음 |
| 위험한 요청 | 실행 전 차단 + 안전한 사유만 표시 |
| 실패/부분 실패 | 성공한 것처럼 표시하지 않고 성공·실패 범위를 분리 |
| 전 과정 | 질문 → 데이터 선택 → 조회 → 검증 → 보고서 trace 유지 |

## 7. 오류 처리 원칙

| 상황 | 시스템 대응 |
|---|---|
| 질문 모호 | "기간, 고객군을 알려주세요" 재질문 |
| 권한 없음 | 실행 전 차단 + 안전한 사유만 표시 |
| 원천 오류 | 어느 시스템이 실패했는지, 재시도 가능 여부 안내 |
| 부분 성공 | 성공분만 결과 표시, 실패 범위 명시(`PARTIAL`) |
| 근거 부족 | 단정하지 않음 + 추가 확인 필요 표시, 보고서 삽입 차단 |

원칙: 기술 에러를 숨기되, 사용자가 수정 가능한 정보만 제시한다. 일반 사용자에게 자유 SQL·원문 DB 오류·credential·모델 내부 추론을 노출하지 않는다.

## 8. 차별점

- 답변의 근거(어떤 데이터, 어떤 조건)를 결과와 함께 제공
- 생성 SQL은 사람 승인 없이도 3단계 자동 검증(컨텍스트 검증 → SQL 안전성 검증 → 결과 검증)을 통과해야만 실행
- 검증된 결과는 Artifact로 보존되어 보고서에서 재사용·자동 재실행 가능
- AI는 질문 해석과 조회 제안만 담당하며, 최종 실행·승인은 고정 규칙과 관리자가 판단
